## 修复「此站点的连接不安全 / localhost 发送了无效的响应」（https 绑定的延续修复）

- 用户报浏览器访问 localhost:5001 出现 `此站点的连接不安全 localhost 发送了无效的响应`（即 TLS 握手失败 / SSL 协议错误）。
- 根因（比上条更深）：上条修复只让应用绑 `http://localhost:5001`，但 `Program.cs` 还有**无条件的 `app.UseHttpsRedirection()`**，且 `if (!IsDevelopment())` 分支会发 `UseHsts()`。用户直接 `dotnet <dll>` 启动默认环境是 **Production** → 发 HSTS 头 → 浏览器把 localhost:5001 记住成"必须 https"。链路变成：浏览器 `http://localhost:5001` → 307 重定向 `https://localhost:5001` → 但 5001 上**只有 http 监听、没有 https 监听** → TLS 握手失败 → "发送了无效的响应"。
- **关键坑**：企图 `UseUrls("http://localhost:5001","https://localhost:5001")` 同端口双协议 → Kestrel 在同一 TCP 端口 5001 上既要绑 http 又要绑 https → `address already in use`（同端口不可同时开 http+https 监听）。故 http 与 https **必须分占不同端口**。
- 最终修复（src/CJDSL.Web/Program.cs）：
  1. `builder.WebHost.UseUrls("http://localhost:5000", "https://localhost:5001")` —— http 走 5000、https 走 5001。
  2. `builder.WebHost.ConfigureKestrel(...)` 手动从 `StoreName.My / CurrentUser` 加载受信任的 ASP.NET Core 开发证书（CN=localhost，已 `dotnet dev-certs https --trust`）作为 https 端点证书；因 Production 环境下 Kestrel 不会自动选开发证书，必须显式加载。无证书时 try/catch 回退纯 HTTP。
  3. `ApiBaseUrl = "http://localhost:5000"`（服务端回连管理接口走 http:5000，与 http 绑定端口一致；https 仅服务浏览器）。
  4. 删除 `app.UseHttpsRedirection()` 与 `app.UseHsts()`（避免再强制/记住 https，且 http:5000 可直接响应）。
  5. `launchSettings.json` 的 `applicationUrl` 改为 `https://localhost:5001;http://localhost:5000`。
- 验证：`dotnet build ... --artifacts-path C:/temp/cjdsl_https2 --disable-build-servers` → 0 错误；`dotnet <dll>`（无 --urls，Production）启动后 `Now listening on: http://localhost:5000` + `https://localhost:5001`；首行日志证明同端口冲突已消除。探测：`https://localhost:5001/`=200、`https://localhost:5001/api/llm/getAllProviders`=200、`http://localhost:5000/`=200、`http://localhost:5000/api/llm/getAllProviders`=200 且返回完整种子供应商列表。**结论：浏览器用 `https://localhost:5001` 即可正常访问（HSTS 升级后也是它），不再报"连接不安全"。**
- 注意：`--urls` 命令行参数在本仓库实测**未覆盖**代码内 `UseUrls`（即代码 `UseUrls` 优先级更高），故真实启动就是 5000/5001，无需额外参数。停掉后台验证任务后 netstat 确认 5000/5001 已释放。
- 提示用户：HSTS 可能已缓存，浏览器会强制跳 https://localhost:5001（现在能正常工作）；若手工输 `http://localhost:5001`（无 HSTS）会连接被拒，应改用 `https://localhost:5001` 或 `http://localhost:5000`。未做 git 提交。

## 修复「LLM 结构化生成失败: JSON 反序列化失败: 无法转换到 TargetPlatform」

- 用户运行 DSL 测试页「LLM 测试」后报：`The JSON value could not be converted to CJDSL.Domain.TargetPlatform. Path: $.targetPlatform`（StructuredLLMClient 在反序列化 LLM 返回的 DSL JSON 时抛 JsonException）。LLM 输出的是 `"targetPlatform": "Web"`（字符串）。
- 根因：`StructuredLLMClient.JsonOptions = { PropertyNameCaseInsensitive = true }` **没有字符串枚举转换器**。System.Text.Json 默认把枚举当**数字**反序列化，遇到字符串 `"Web"` 直接失败。且 `DslTest.RenderDsl` 用 `{ PropertyNameCaseInsensitive = true }` 把文本框 JSON 反序列化为 Blazor.DslPage —— 同一坑，生成结果填入后再"渲染"也会炸。两处都缺枚举转换器。
- `TargetPlatform` 枚举成员：`Web/Wpf/Maui/React/Vue`；`DslPage` 里唯一的枚举就是这个，其它都是 string。Prompt（`DefaultSystemPrompt`）已列出合法值 `"Web|Wpf|Maui|React|Vue"`，故 LLM 输出 "Web" 合法，纯属反序列化不支持字符串。
- 修复（两个枚举都加**健壮枚举转换器**，覆盖 LLM 路径与渲染路径）：
  1. 新增 `src/CJDSL.Domain/FlexibleEnumConverter.cs`：通用 `FlexibleEnumConverter<TEnum>`（非 sealed，可被子类继承）。`Read`：数字→`Enum.ToObject`；字符串→`Enum.TryParse(ignoreCase:true)`（大小写不敏感，"Web"/"web"/"WEB" 均可）；未知字符串→回退默认成员（Web）；`Write`→输出枚举名字符串（如 "Web"）。
  2. `src/CJDSL.Domain/ValueObjects/GenerateOptions.cs`：`TargetPlatform` 加 `[JsonConverter(typeof(DomainTargetPlatformConverter))]` + 子类 `DomainTargetPlatformConverter : FlexibleEnumConverter<TargetPlatform>`。
  3. `src/CJDSL.Blazor/Models/DslModels.cs`：`TargetPlatform`（Blazor 版）加 `[JsonConverter(typeof(BlazorTargetPlatformConverter))]` + 子类 `BlazorTargetPlatformConverter : FlexibleEnumConverter<CJDSL.Blazor.Models.TargetPlatform>`（需 `using CJDSL.Domain;`，Blazor 已引用 Domain）。
- 安全性核对：`TargetPlatform` 的 JSON 序列化点只有 `DslPage`/`GenerateOptions`（改为字符串更合理）；WPF 走内存 `DependencyProperty`、API `[FromQuery] TargetPlatform?` 走 ASP.NET 查询绑定（不受 `[JsonConverter]` 影响），无依赖"数字形态"的 JSON 契约 → 零副作用。
- 验证：`dotnet build CJDSL.sln --artifacts-path C:/temp/cjdsl_enumfix --disable-build-servers` → **0 错误**。新增 `src/CJDSL.Tests/TargetPlatformJsonConverterTests.cs` 10 项用例（字符串大小写/数字/未知回退/序列化回环），`dotnet test` → 10/10 通过；全量测试 **25/25** 通过（原 15 + 新 10），无回归。
- 注意点（踩坑）：① 通用转换器初版误写为 `sealed` → 子类继承报 CS0509，去掉 sealed 解决；② 不要只用标准 `JsonStringEnumConverter`，它在部分 .NET 版本会拒绝数字且对未知字符串抛异常，自定义回退转换器更稳（LLM 边界容错）。未做 git 提交。
