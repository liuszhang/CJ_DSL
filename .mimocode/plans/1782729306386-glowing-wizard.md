# CJDSL 多平台渲染支持 — 实现计划

## 目标

在 DSL 核心模型中引入 `TargetPlatform` 概念，使一套 DSL 能够在不同 UI 平台（Web/Blazor、WPF、MAUI、React 等）上渲染，体现"一套 DSL，任意平台动态生成界面"的核心理念。

## 当前问题

- DSL 模型（`DslPage`、`DslComponent`）虽然数据结构是平台无关的，但**没有声明目标平台**
- 渲染器（`IDslComponentRenderer`）返回 `RenderFragment`，绑定 Blazor
- LLM 生成时只知道 `DeviceType`（桌面/移动端），不知道目标 UI 框架
- 没有正式的平台枚举，`DeviceType` 只是字符串

## 设计方案

### 1. Domain 层 — 新增平台枚举和模型

**文件**: `CJDSL.Domain/ValueObjects/GenerateOptions.cs`

新增 `TargetPlatform` 枚举：
```csharp
public enum TargetPlatform
{
    Web,        // Blazor / 纯 Web
    Wpf,        // WPF 桌面应用
    Maui,       // .NET MAUI 跨平台
    React,      // React 前端
    Vue,        // Vue 前端
}
```

**文件**: `CJDSL.Domain/Entities/Dsl/DslPage.cs`

在 `DslPage` 上新增属性：
```csharp
/// <summary>目标渲染平台</summary>
public TargetPlatform TargetPlatform { get; set; } = TargetPlatform.Web;
```

**文件**: `CJDSL.Domain/ValueObjects/GenerateOptions.cs`

在 `GenerateOptions` 上新增属性：
```csharp
/// <summary>目标渲染平台</summary>
public TargetPlatform TargetPlatform { get; set; } = TargetPlatform.Web;
```

### 2. Infrastructure 层 — LLM 提示词感知平台

**文件**: `CJDSL.Infrastructure/LLM/DslPromptBuilder.cs`

- `BuildSystemPrompt()`: 在 Schema 规范中加入 `targetPlatform` 字段说明
- `BuildFormPrompt()`、`BuildListPrompt()`、`BuildNlpPrompt()`: 在用户上下文中注入目标平台信息
- 指导 LLM 根据目标平台调整组件类型映射（如 WPF 用不同组件名）

**文件**: `CJDSL.Infrastructure/LLM/DslResponseParser.cs`

- `Parse(JsonElement)`: 解析 `targetPlatform` 字段

**文件**: `CJDSL.Infrastructure/Services/TemplateDslGenerator.cs`

- 各生成方法中考虑 `TargetPlatform` 对布局的影响

**文件**: `CJDSL.Infrastructure/Services/LlmDslGenerator.cs`

- 缓存键和生成逻辑中包含 `TargetPlatform`

### 3. Application 层 — 命令和 DTO 传递平台

**文件**: `CJDSL.Application/Dsl/Commands/GenerateDslCommand.cs`

- 缓存键中加入 `TargetPlatform`
- 命令参数已通过 `GenerateOptions` 间接传递

**文件**: `CJDSL.Application/Dsl/Commands/GenerateDslFromNlpCommand.cs`

- 同上

**文件**: `CJDSL.Application/Dsl/DslDto.cs`

- `GenerateDslRequest` 和 `GenerateFromNlpRequest` 已包含 `GenerateOptions`，无需修改

**文件**: `CJDSL.Application/Dsl/Queries/GetDslQuery.cs`

- `GetDslQuery` 的 `Device` 参数扩展为支持平台查询

### 4. API 层 — 端点支持平台参数

**文件**: `CJDSL.Api/Endpoints/DslEndpoints.cs`

- `GET /api/dsl/page/{pageCode}`: 将 `device` 查询参数语义扩展为支持 `platform`
- `POST /api/dsl/generate`: 请求体已包含 `Options`，自动传递

### 5. Blazor 层 — 渲染器适配（基础）

**文件**: `CJDSL.Blazor/Models/DslModels.cs`

- `DslPage` 模型（Blazor 侧副本）同步新增 `TargetPlatform` 属性
- `DslRenderContext` 新增 `TargetPlatform` 属性，供渲染器读取

**文件**: `CJDSL.Blazor/Components/Renderers/DslPageRenderer.razor`

- 将 `TargetPlatform` 传入 `DslRenderContext`

> **注意**: Blazor 渲染器本身不需要改变——它是 Web 平台的实现。未来新增 WPF/MAUI 渲染器时，每个平台有自己的 `IDslComponentRenderer` 实现。

## 实施顺序

1. **Domain 层**（枚举 + 模型）— 基础，其他层依赖
2. **Infrastructure 层**（提示词 + 解析器 + 生成器）— 核心逻辑
3. **Application 层**（命令 + 查询）— 传递层
4. **API 层**（端点）— 对外接口
5. **Blazor 层**（渲染上下文）— 渲染侧适配

## 验证方式

1. `dotnet build` 确保编译通过
2. 检查 `DslPage` 序列化/反序列化包含 `targetPlatform`
3. 检查 LLM 提示词中包含平台信息
4. 检查缓存键包含平台维度
